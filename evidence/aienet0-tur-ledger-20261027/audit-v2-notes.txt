A1: failed fsync followed by an unsynchronized duplicate acknowledgement
---------------------------------------------------------------------
Before: first injected fsync EIO returned 3 but left the prefund record in the journal;
the second injected invocation returned 0/dup. All four mutation duplicates returned 0
without any journal fsync. The same audit assertions fail against the archived before source.
After: each of two injected fsync failures returns 3, emits no acknowledgement, and restores
exact original bytes and size; audit finds no torn tail. The clean retry actually writes,
fsyncs and acknowledges prefunded. For prefund/reserve/settle/refund duplicates, injected
fsync EIO returns 3 without output or journal mutation; clean retry synchronizes the actual
journal fd before stdout. The test resolves that fd from strace openat output, so a directory
fsync cannot accidentally satisfy this assertion. Directory durability is also required.
The append's rollback is best-effort: if rollback itself fails, no success is acknowledged;
a later valid retry must still cross a fresh journal and directory durability barrier.
Mutants no-sync-rollback and no-duplicate-sync are both killed. Existing no-fsync is killed too.
